# DSH 执行目标修订

状态：2026-10-09 本人明确决定“改成 DSH，不再适配 Codex”，随后撤回 DSH 配套认证组件，要求优先由 Hermes 管理专用 DSH 执行实例。本修订与[首版规格](hermes-plugin-v1.md)共同构成当前实施契约；发生执行器差异时以本修订为准。组织、飞书公开协作、资料、仓库边界和生命周期要求保持原规格；Desktop 手动接入的受影响范围如下明确记录。

## 接入范围

开发执行目标仍为 DSH，默认优先由 Hermes 管理专用 DSH 执行实例，不再要求复用本人正在使用的 Desktop 共享后端。Hermes Profile 负责调度、监督、消息和资料，DSH 承担实际开发；插件使用原生 Hermes 平台、工具、Hook、后台任务和卸载接口。Hermes、DSH 及第三方 SDK 源码保持原字节，不全局 monkey patch，不替换宿主 logger／信号处理，不复制修改 SDK。

此前允许纳入 DSH 配套认证插件的决定已撤回。认证 URL 导出、发布文件和导入器不再属于方案，相关新增实现及组件专属门槛已移除；不开发、安装或启用该组件。仅继续实施 Hermes 主插件，保留其他已有修改与已确认需求。

专用实例使用明确隔离的 home、原生受支持启动方式及本插件的实例归属记录。默认 `mode: owned_native`。Hermes 主插件启动自有 Node 子进程，调用原 DSH 的 `runProfile` 和进程内 `typertGateway`，不注册额外 DSH 插件。原安装包只由受限 `runtime_package_root` 引用，不复制或修改源码。

实例启动、重连、停止和资源清理核对实际进程及当前状态。当前源码及测试须按原始 SDK 验证，模型、实际执行、控制和写入门槛分别验收。插件不修改原 Desktop 或其配置，不为复用 Desktop 新增认证导出体系。

专用实例和显式远端均使用原 Gateway 的单次调用、逻辑流、当前生成的参数和结果。插件自有进程通信只承载这些结果，不把旧 JSONL、thread／turn 方法或权限字段重新命名成 DSH 协议。插件只能清理自己拥有的连接、任务、订阅和专用进程；共享或手动实例不随插件卸载而停止。专用实例可承担新开发任务，但不能替代原 Desktop 会话的观察或接管。

Desktop 手动会话观察／接管保留为非默认接入。必须有获准的独立原生连接，并重新核验原实例、范围和当前控制能力；没有该连接时明确显示不可观察／不可接管与覆盖未知，不克隆其 home 或另开实例读取历史来冒充原执行。只观察、本次授权接管、归还不打断及手动执行阻塞同仓库的规则保留，但不得宣称默认专用实例已覆盖 Desktop。

现有项目使用登记的本地仓库，不因执行器改变 clone 在线仓库。只有调度职责、没有自身仓库的项目总负责人不运行开发或全局验证；明确登记 mono 的负责人继续承担自身开发及稳定父子组合测试。子负责人仍只承接明确分配的 Issue。

## 配置与持久状态切换

当前管理状态使用 `schema_version: 2` 与 `executor_engine: dsh`。开发连接引用为 `Profile.connection_refs.dsh`，受理时冻结 `accepted_dsh_ref`；默认实现为 `DshOwnedAdapter`，非默认显式远端使用 `DshRemoteAdapter`。这些是插件私有契约，不是 Hermes 或 DSH 的原生字段。

受限原生 `dsh_executors` 是连接引用到已配置执行器的映射，每个 key 必须与配置内 `service_ref` 完全一致。默认专用配置要求 `dsh_home`、本地 `workspace`、`runtime_package_root` 和 `service_ref`；可选 `node_bin` 和 `timeout`。路径须为规范绝对路径，workspace 已存在，home 位于 workspace 之外且仅本人可访问。原安装包目录须包含 `@deepseek-ai/dsh/lib/profile-boot.js`。省略 `node_bin` 时使用本机 Node，不接受任意命令或环境变量数组。

各专用实例沿用自己的原生 Profile 配置选择模型和预算，不复制已有 Desktop home。一个管理实例依据已受理的连接引用及原 Session 绑定选择对应实例；错引用、未知引用或二者冲突不能落到其他项目的实例。旧 singular `dsh_execution` 仅在 service_ref 匹配时保留兼容，不能成为任意项目的默认回退。多个本地项目可以使用不同固定 workspace，无需任务结束后 reload 整个 Hermes。

可信原生配置登记专用实例的明确 home、归属和原生接入引用；单独获准的既有远端必须显式选择 `mode: remote`，才可登记 `base_url`、`service_ref`、`source_kind` 和 `endpoint_ref`，不能把远端字段隐式解释成默认模式。必要凭据仅取自仓库外受限原生配置，在自有客户端内存中使用，不增加认证 URL 发布或导入流程。公开管理请求不能传入 cookie、URL、命令、verifier 或 `enabled` 来改变实际服务或执行器映射。真实 URL、home、仓库路径、Profile／用户／应用标识和密钥不进入源码、夹具、版本化文档、公开工单或普通日志。

启动须先只读核对数据库完整性和 engine/schema。旧执行器状态、旧连接引用和能力收据默认拒绝自动采用，不就地改写 engine 来解除门槛。切换安排必须保留检查点、明确停止和封存意图、未知发送结果、仓库占用及受保护历史；原未决输入、批准和启动不得重放到 DSH。原始历史可作为受保护只读资料继续保留，不继续提供 Codex 在线观察、执行或控制。

DSH 服务身份与插件连接代次分别记录。认证通过、相同会话 ID、home 或历史均不足以证明原执行实例相同。核对实际进程／启动代次、原服务来源、版本与配置摘要；重启或身份变化后的记录显示待对账，不能凭新服务空列表释放旧仓库占用。

## 当前一手接口依据

以下来自可读的原始 DSH 文档／源码，只说明接口存在及其语义；它们不是当前运行实例的验收结果。实际版本、来源摘要和探针结果保存于仓库外受限证据。

默认专用实例使用本机原安装包公开的 `runProfile`。首次从原 web 模板建立独立 `hermes-owned` Profile，之后沿用同一专用 home 的原生配置。原服务仅监听 loopback 随机端口，关闭自动打开浏览器和 URL 输出；插件通过自有进程通信调用进程内 `typertGateway.invoke` 与 `wireStream.open`。模型和预算由原生 Profile 配置确定，不构造不存在的 Gateway 参数。

原 `$events/result` 属于特殊 RPC，不在普通 invoke registry 中，原事件流的上行也不能代替它。该结果须经公开 `createSharedFetchHandler('/api').fetch` 的进程内 Request 进入原解析和派发，再回到原事件来源。无模型探针已核对该载体，以及冷启动／重启、空 Session 列表、control 基线、ready 代次、shutdown、监听器关闭和原 SDK 字节不变。此证据仅覆盖接入，不证明真实人工请求、控制、写入、模型或恢复业务已通过。

Session 创建、prompt 受理、事件、回合和执行终态分别核对。受理已知但回合未知时保留输入回执和占用，不重复发送。同实例追加使用原生队列，不冒充 steer。已释放旧工作后可在同 home 创建新实例代次；旧未决输入、事件和控制授权不会转移。关闭自有 Node 子进程也不证明全部相关 OS 执行已退出。

下面的表列出原 Gateway 接口依据。专用实例接入和非默认远端接入分别取得实际证据；接口存在不表示当前适配器已开放全部能力。历史、控制、恢复与人工请求要求继续保留，缺少接入或当前证据时保持不可用。原生问题和审批须接入正式路径，不能用普通 prompt 假装回应；未验证可用界面时也不能生成虚构定位。

| 边界 | 接口依据 | 插件必须验证的行为 |
| --- | --- | --- |
| 原生传输 | 专用实例的 Gateway invoke／wireStream；显式远端的 `/api`、`/api/remote.mux`；原 `$events` ready 基线 | 实例身份、原参数与结果、错误结果、generation、断线和资源清理；远端另核对认证 |
| 只观察 | Session Controller 的 list、page／follow、projections；读取历史不激活 cold Agent | 完整授权范围、分页与游标连续性、当前基线、不会 resume／create／prompt／答复 |
| 独立任务 | Session create 与 prompt，稳定 `requestId` 对应 durable inbox／用户来源 | 意图先落盘，独立 Session，正确本地 workspace，重复受理不产生第二次执行 |
| 追加和停止 | Session prompt／队列／cancel；job list／follow／kill 与子 agent 来源 | 原 Session／turn，不误送，排他控制与输入竞态保障，相关执行实际终止 |
| 普通问题 | `userQuestions.answer`、open／continued／settled 投影 | 原调用仍有效、本人或允许事实答复、continued 路径可能恢复 Agent，不自动开新工作 |
| 操作审批 | Agent-scoped `approval/request` waterfall 与一次性 outcome | 原活请求、本人明确决定、具体操作可审阅、竞争与取消、一次性原响应 |
| 重连和恢复 | generation ready、事件／投影基线、历史续读与 gap repair | 旧 transient 值不跨代继承，未知结果先对账，旧批准和控制不重放 |

Session writer lock 防止持久资源竞争，不能直接证明不同客户端只有一个控制负责人。Session cancel 也不单独证明所有 shell 后代、job、子 agent 和定时执行已停止。缺少相应当前运行覆盖时继续保留占用和停止处理中。

DSH 审批请求提供工具名、reason 和可选 call ID，不保证包含完整工具参数。材料不足以判断具体操作、文件补丁、网络及范围时，只给原 DSH 界面定位；不能从 reason 拼出授权，也不能用普通 user prompt 代替审批答复。一次性允许不扩展目录职责、仓库写集、资料授权或长期策略。

## 原验收如何延续

原首版 16 组场景及完整需求清单继续有效；18 张子工单仍负责对应业务范围。执行器专用场景以 DSH 重新取得证据，不把原 Codex 协议探针或切换前 658 项测试标成 DSH 通过。

1. 原实例的只读发现：专用实例只查询登记项目范围；Desktop 属于非默认的独立原生接入，缺连接时明确不可观察／接管。分别核对完整 Session／子 agent／job 范围与缺口；专用实例空列表不等于没有 Desktop 手动执行。
2. 一项 Issue 的独立 Session：身份／真实 @／受理锚／冻结验收／仓库基线齐备后派发，核对输入与原服务受理、实际进展、终态、测试及交付。
3. 原 Session 控制：当前工作内接管，唯一负责人；追加／停止／明确继续与预期 turn 关联；归还不取消正在运行的原执行。
4. 人工请求：入口群集中通知、原任务关联、普通问题与审批区分、秘密到原界面；原 UI 竞争、过期、断线、重复和未知回送不重放。
5. 写入和执行覆盖：允许自身源码／Git／测试产物，拒绝子仓源码和 Git、祖先 rename、原子替换、symlink、已有／新 hardlink、越界路径及子进程逃逸；所有工具、MCP、shell 和后台入口同样受控。
6. 恢复：仍执行只恢复监督；原工作未完成、原授权及边界有效、全部相关执行已停止且无主动停止／封存意图才继续；不能确认时保留未知及占用。
7. 公开协作、资料和生命周期：真实跨群 @、分段消息及回送；查询授权和实际新会话加载；父子封存、父先恢复、子逐个恢复、档案保护及检查点回退继续完整验收。

全局验证继续要求获准动作准备子版本、父不 checkout 子仓、稳定版本占用、持续输入变化观察、真实 runner 退出和固定版本测试证据。切换执行器不解决既有 hardlink 边界反例，不能以权限 preset、cwd 或静态收据替代实际保护。
