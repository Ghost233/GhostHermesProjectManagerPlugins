# 内部交接与开发任务优先

2026-10-10，用户确认负责人之间内部派发任务。飞书呈现关键交接、需求分歧、接口变更、阻塞问题和结果，用户仍可直接 @ 各负责人或独立助手。相较于群内真实 @ 交接，这个选择减少了任务派发对群消息投递和公开答复的依赖。

首版先完成项目、负责人和本地仓库绑定，以及 Issue 开发测试、DSH 控制、进展汇报和人工问题处理。完整资料迁移、历史档案管理与自建 WebUI 留到后续阶段重新取舍。用户确认当前没有残留运行任务，旧实现仍处于开发中，可以替换未完成的设计和实现；首版不承接旧运行任务的迁移。

本记录覆盖重新讨论中已确认的交接方式和首版范围。讨论依据与后续决定索引见[简化方案](../planning/hermes-plugin-simplification.md)，当前实现契约见[简化首版规格](../specs/hermes-development-coordination-v2.md)。用户已调用 to-spec 并确认公共测试接缝，旧规格和旧测试结果只作为已有方案的参考。
