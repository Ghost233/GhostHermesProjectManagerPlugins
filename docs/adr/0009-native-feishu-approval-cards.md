# 执行审批默认使用飞书卡片

2026-10-11，用户确认把执行审批改为飞书卡片。此决定修改 [ADR 0008](0008-owner-feishu-operation-approval.md) 的默认入口，保留本人答复同一原 DSH 单次审批的权限边界。普通问答继续使用原文字入口，唯一审批编号的文字答复保留为备用方式。

卡片展示可以安全分享的完整原操作材料，仅提供“批准一次”和“拒绝”。点击来源取自原 SDK 的 `card.action.trigger` 回调。主插件核对原操作通知、本人身份、工作、外层卡、Session、实例代次、审批、调用和命令摘要；按钮里的身份声明不作为授权来源。

回调的即时回应只表示正在核验。本人决定已受理、原审批决定和实际工具结果分开显示。已受理、结果未知、已处理或过期的卡片移除操作按钮；重复点击不能再次执行，未知决定先核对原审计。材料不能安全公开时保持受阻。

卡片沿用主插件已有的原 Python SDK 连接、消息 API 和授权链，不修改 SDK，不增加派发队列、认证组件或模型可见审批工具。后台保持无界面运行。原 SDK 的本机协议测试仅证明兼容性；应用回调订阅与发布是否生效、真实群内点击和结果回传仍须另行取得真实证据。当前用户已选择稍后进行真人验收，工单和阶段保持开放。

## Hermes 原生命令确认

2026-10-12，用户要求补齐 Hermes 原生命令确认卡。插件自己的平台适配器实现原生 `send_slash_confirm()`，提供“一次批准”“始终批准”和“取消”。点击结果送回 Hermes 的原确认请求；DSH 执行审批继续使用上面的单次批准和拒绝规则。

卡片绑定原 Profile、会话、确认编号和已核验的消息来源。主插件核对点击者、应用、群、原卡片、会话和当前待确认请求，拒绝越权、过期、重复与串会话点击。处理完成后更新原卡片并停用按钮。卡片不支持、发送失败、送达未知和已送达分别记录，文本回退沿用 Hermes 原入口。

“始终批准”遵循原命令的持久设置。卡片必须说明后续影响；对 `/new`、`/reset` 和 `/undo`，它会关闭后续破坏性会话命令的确认。单次批准和取消不改变这项设置。真实测试先保存必要会话记录；持久改变设置的实机测试另行取得授权。

针对性测试使用原平台注册、消息事件、Hermes 确认和飞书卡片回调入口，仅替换外部服务。实际验收覆盖当前 Hermes 与原群中的 `/new` 单次批准、取消和无效点击。两类卡片都只修改主插件，不修改 SDK、扩大权限或增加审批系统。
