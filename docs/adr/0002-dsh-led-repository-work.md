# DSH 主持仓库内工作流

2026-10-10，用户确认 DSH 主持仓库内的 Matt 流程。Hermes 负责人分派完整工作范围，DSH 负责详细拆分、实施、测试和审查，Hermes 监督范围、进展、人工问题和交付。相较于 Hermes 拆细后逐票调用 DSH，这个选择减少了重复派发，保留各仓库独立细拆的能力。

首版只管理 Hermes 为项目创建的专用 DSH 实例与任务。Desktop 手动会话的观察和接管留到后续重新决定。人工应答须关联原 DSH 任务，呈现方式见[人工应答决定](0004-feishu-questions-and-native-approvals.md)。实际往返仍须验证。

## 当前同实例接入

2026-10-12，用户要求复用当前 Launcher 启动的同一个 DSH Desktop 后端。此决定替代上面的专用实例选择。允许为项目新建普通会话，开发提示词、工具、测试和状态须在现有 Desktop 中可见。插件只控制自己新建并登记的会话及其作业，保留已有手动任务。

用户另行允许在 Hermes 主插件包内加入小型 DSH 原生 Hook，通过原 Loader 和新 agent-preset 加载。Hook 按受管会话核对归属、工具、沙箱和预算，不修改 SDK，不新建运行时、认证组件或模型工具。最初授权包括代码、测试和准确配置差异；实际加载依据当前明确授权和具体计划执行。

请求前检查已报告用量与请求计数，和保证最后一次调用绝不跨过累计 token 额度，是不同的保证。后者须有经过验证的预留边界。缺失、损坏或结果未知时保持受阻，不把 Goal 轮数、目录标签或事后取消当作等价证明。

## 独立运行时退役

2026-10-12，用户确认封闭旧独立运行时的启动和回退入口。旧配置的缺省启动、显式 `owned_native`、非共享执行引用和历史 work 的非共享派发须在准备 Home 或进程前拒绝。原文件、配置、会话和失败证据保留，不自动迁移或释放占用。

历史独立载体测试使用 `retired_independent_runtime` 标记，默认回归明确列为未选中。原 EOF 退出失败和强制清理仍是历史失败，不能改称通过。共享 Desktop、飞书自有平台、身份、问答、审批、停止及生命周期的有效覆盖继续执行。复用原 SDK 的外部服务测试夹具不属于生产独立运行时回退。

下一阶段先验证有限真实工作：原群请求进入原 Kanban，同一 Desktop 的普通会话可打开，提示词实际送达，DSH 执行并引用原消息回传。完整开发验收随后继续，沿用已批准的累计预算。

## 工作区与会话归属

已绑定的本地仓库根目录通过原生 `workspace/create({path})` 复用或登记工作区，保存其 `workspaceId`。该接口也用于核对原路径和 `sessionIds`，不增加通用工作区管理入口。创建会话使用 `workspaceId`，不能同时传 `cwd`。

已有受管会话先核对目录、原会话身份和历史，再用原生幂等 `session/create` 补齐归属；会话 ID、提示词、任务关联与累计预算保留。重载后继续核对对应关系，错误目录或非本工作会话拒绝。工作区归属和工具目录是分别验证的行为，不能仅据前者缺失解释执行失败。

核心门禁按共享 Desktop、原生 Kanban 与飞书的实际注册路径选择，数量不作为目标。有效业务断言保留；重复或只检查内部布局的断言合并；已退役运行时仅保留相关变更触发的历史回归与当前入口拒绝测试。删除无用途测试或未选中历史用例不改变其原失败结论。已有有效基线复用，新增修改只运行定点与受影响验证。

## 原会话维护后续接

用户同意将一次当前后端的受控维护重启纳入方案。主插件只为已接受首输入、模型请求尚未开始且已明确失败的原工作准备检查点；本人维护后再次明确继续。旧进程必须结束，原 SID、创建时间、目录、preset、工作区、完整历史快照和预算须核对一致，配置只允许连接代次变化。

受理后保留原失败、首请求和 worker 记录，当前状态为等待续接，原卡仍由原生 Kanban 派发。新请求使用独立编号并携带完整冻结任务范围，不重用旧 RPC；未知提交保留待核对，不重送。新终态必须位于检查点之后。主 Hook 用 Launcher 已公开的实例标识核验当前代次，预算上限、状态和计数保持；不通过旧 preset 的私有句柄热换，也不修改 SDK。
