# DSH 原请求人工应答（[将群内答复送回有效问题与审批](../../../../issues/21)）

2026-10-09 起只接入 DSH。原服务的普通问题、非阻塞 continued question 和一次性审批有不同生命周期，不能用旧 JSON-RPC request 形状或新 prompt 假装统一回应。总体规则见[DSH 执行目标修订](../specs/dsh-executor-transition.md)。

## 身份、关联与一次处理

`Manager.answer_human_request(identity, request_id, human_request_id, reply_id, response)` 是公共入口。认证 bridge、Dashboard 与原生工具共用身份及控制检查；participant 不借 Owner alias。可见任务、机器人职责或转述本人旧指令不能成为本人新决定。

稳定 reply ID 绑定原请求、实际本人／允许事实答复者、原 Session／turn／调用、服务／连接代次和答案。相同答复返回原记录，不重发；不同内容拒绝。原 UI 先处理、请求撤回、停止／交付／归还、任务范围或连接状态冲突使旧可答句柄失效。历史问题和旧审批不能重新构造活请求。

发送前核对原请求仍有效、当前控制、仓库／资料范围与实际交互形态。先持久答复意图，最多一次送回原正式路径。收到、送回、原请求处理和后续操作／执行结果分别显示；发送成功不等于批准执行成功。未知结果只读对账，不能换 ID、旧连接或新 prompt 重放。

## 普通问题与 continued 生命周期

DSH User Questions 以原 call ID 和逐题 ID／选项验证 answer。open 请求在原活调用内回答；continued 问题的回答可能 resume root 并排队 user-question-reply，形成新 turn，不能伪造已结束工具的结果。

插件只有在本次工作、控制、原请求和实际执行安排仍有效且已验证该 continued 路径时才允许回送。停止、工作完成、归还、只观察、未知状态或迟到材料不自动唤醒 Agent；缺可靠生命周期或排他输入保障时定位原 DSH 界面。未答复不默认批准／拒绝／停止。

负责人仅在已授权资料范围内回答可核实的已定事实并附来源。新需求、取舍、操作授权、选项问题、明确要求本人或无法核实的内容交本人，不能由 Wiki 或上级代批。

## 一次性操作审批

DSH approval/request 由 Agent-scoped waterfall 路由。一次性 outcome 仅适用于原请求，不改长期 policy、项目绑定、资料授权或仓库写集。普通“继续”“好的”、自然语言 prompt 和 userQuestions 的选择不自动成为执行批准。

原请求可能只有工具名、reason 和可选 call ID，不保证完整参数。具体文件／补丁／命令／网络及影响范围不足以审阅时只展示原界面定位，不拼接缺失参数。取消或已决定的请求丢弃迟到答案；原 UI 竞争、连接失联和控制归还后不能缓存批准供未来使用。

专用实例的原 `$events/result` 走 Gateway 特殊 RPC。普通 `invoke` 和事件流上行不能代替该接口；载体通过公开 `createSharedFetchHandler('/api').fetch` 的进程内 Request 进入原解析和派发。无模型载体验证只证明原请求结果能回到原来源，真实审批的范围、有效性、竞争和后续执行仍须分别验收。

敏感请求只返回安全定位，不把秘密题干、选项、答案、凭据或不足以判断的脱敏审批写入群、管理状态、记忆或日志。无正式可用链接时不给虚构 URL。

## 群内闭环

入口群集中 @ 本人，保留项目／Issue、原问题、是否阻塞、有效选项和任务锚。本人在入口或项目群回复，按引用或明确请求 ID 唯一关联；多个候选登记澄清，不选最近任务。跨应用和群核对实际 app／tenant／sender／recipient／chat，总管只转交本人决定。

明确“回答”与针对具体操作的“批准／拒绝”分别解析，审批必须让本人核对当前操作摘要与一次性范围。反馈沿原任务 outbox、真实 @ 和原群引用；未知群投递也不换 UUID 重发。15／15／2／30 分钟监督与通知规则保持原要求。

## 验证门槛

离线使用 DSH 原生问题／审批生命周期、合成身份与未经修改 Hermes SDK 验证一次答复、错误请求／身份、非阻塞、continued、原 UI 竞争、取消／停止／归还、重连、秘密和未知不重放。真实 DSH 原实例与飞书闭环独立验收；接口源码或原执行器的旧应答测试不能启用 DSH 回送。
