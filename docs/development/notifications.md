# 定期汇总与待处理提醒

2026-10-09 执行目标修订：当前优先由 Hermes 管理专用 DSH 执行实例，停止 Codex 适配，配套认证组件已撤回；Desktop 手动接入非默认，缺获准独立原生连接时不可观察／接管，见[DSH 修订](../specs/dsh-executor-transition.md)。本文保留的旧 JSONL／stdio 协议 peer、旧执行器收据和既有测试描述是迁移前历史证据，不证明 DSH 通过。业务授权、资料保护、写入与生命周期门槛继续有效，执行相关路径须按 DSH 重新验证。

统一管理入口 `run_notifications` 从原服务观察、当前接受责任、人工请求、交付、全局验证和生命周期事实生成通知。`read_snapshot.notifications` 与 Dashboard 使用同一账本；通知不生成新的工作授权。

有运行或等待工作时，每项目 15 分钟汇总负责人、状态、进展变化、阻塞、有效待处理事项和下一步。无活动时不发送定期汇总。原服务、停止处理、任务交付和 PR 状态分别显示，未知执行不转成失败或完成。

已核实执行 15 分钟没有可核实变化，先重新读取原服务，再核查完整相关线程、后台终端分页和当前宿主进程覆盖。明确等待、当前长操作和缺少完整覆盖均不产生疑似停滞判断。告警不会因静默中断或另开执行。原通道持续 2 分钟不可核实通知一次；真正恢复核查后更新一次。

有效审批和需本人回答的阻塞问题立即进入入口群通知；仍有效且未答复时 30 分钟提醒一次。非阻塞问题随汇总。回送、停止意图、控制失效或原观察未知时停止提醒，发送前再次核查有效性。敏感请求仅公开原界面定位。公开结果及普通汇总不额外 @ 本人，真实角色交接仍 @ 接收负责人。

子交付通过原 Owner 来源和已登记角色回传到原父请求的公开协作账本。返工引用原失败验证及明确修复 Issue。已核实停止、稳定组合项目完成和完整封存事件各更新一次；重复受阻事实不形成新告警。封存只消费真实 `lifecycle_events` 中关联已完成操作的 `archive_completed`；审定版本与 Profile 范围保持不变。

入口路由冻结登记的总管群、Owner 命名空间和 Profile 绑定；发送前用原 Lark 客户端核实 bot 身份。每段有自己的 UUID、持久发送意图和实际回执，本群新建锚点后只回复本群实际消息。未知投递不自动重发，也不把最后一段的结果冒充全部投递。Owner 可引用实际已送达的提醒消息回答原请求。

SQLite 保存通知事件与投递事实；插件自己的 `notification-health.json` 保存当前组件健康及定时运行元数据。健康、首次定时登记和无变化的观察不推进权威版本；真正任务变化、新事件和投递仍使用原事务。重启重新计时，不补刷每个错过的 tick。该健康文件不随生命周期 SQLite 检查点回放；卸载显示不可用，失去两次 5 秒检查的健康显示待核实。

离线回归使用可控时钟、原 JSONL 协议的合成服务、真实固定 Hermes SDK Gateway 和原 Lark 构造器。公共测试覆盖全部四个阈值、审批／敏感问题、停止与答复失效、长命令／等待／后台覆盖、部分未知投递、跨群实际定位、真实批准封存流程和重启。真实网络群验收仍为 `unverified`；正式安装、bot 开通和真实资料迁移另行安排。
